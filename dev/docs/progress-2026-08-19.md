# Development record for 2026-08-19

This was the first day the custom stack exchanged bidirectional traffic with the test headphones.

## Problems identified

1. Firmware was not missing. USB capture showed the controller answering immediately after connection.
2. HCI control transfers used the wrong recipient bit. The adapter accepted the USB request but discarded the command without a response.
3. Two receive pumps competed for packets on the same transport. Responses could reach the controller queue while the link queue waited forever.
4. Incoming ACL packets used a different Packet Boundary flag from outgoing host packets. Valid responses were discarded by the parser.
5. Unoptimized P-256 operations in a debug build exceeded the headset SMP timeout. Dependency optimization fixed the pairing delay.

Each fault produced similar symptoms: a successful local operation followed by silence. Packet-level tracing was essential for separating transport, routing, parsing, and timing failures.

## Additional improvements

- Extended LE scan and connection commands
- Scan results that include devices before PACS becomes visible
- Detailed HCI, ACL, and ISO monitoring mode
- Immediate Disconnection Complete handling
- Cleanup of stale events between connection attempts
- LE host feature configuration required for CIS
- Correct detection of 32-bit float versus integer PCM
- 24-bit and 32-bit integer audio conversion
- VB-CABLE default-device configuration through Windows audio policy APIs

## Hardware result

The Realtek controller answered HCI commands, extended scanning found the JBL Tune 780NC and nearby devices, an LE connection was created, and the headset answered the SMP Pairing Request. ATT and SMP packets flowed in both directions.

At that point, full pairing verification, PACS negotiation, CIS creation, and stable playback still required further work. Those areas became the next development milestones and are tracked in `plan.md`.
