# 4.0.2 — Bluetooth flow control and recovery

## Fixed defects

- HCI Number Of Completed Packets is an array of `(handle, count)` pairs. The
  previous parser interpreted it as two arrays, including in its test fixture.
  Batched confirmations for ACL and both CIS streams could therefore credit the
  wrong stream and eventually stall stereo. Truncated events are now rejected.
- Private-address bond discovery used the controller scan callback backwards:
  a neighbour ended the scan, while a matching headset continued it. It now
  skips neighbours and stops immediately on the matching identity/RPA.
- A successful connection racing Create Connection Cancel used to be discarded
  as if it had failed. A timeout now adopts that connection; user cancellation
  explicitly disconnects the late ACL before returning.
- Background HCI command acknowledgements could consume a foreground response
  with the same opcode. Ownership is now tracked in submission order.
- GATT reassembly now accepts only the current ACL handle. Queued packets from
  an old connection and microphone ISO traffic cannot corrupt a fragmented ATT
  response during stream teardown or reconnect.
- Playback and silence-wait loops now confirm ATT indications and consume their
  values, as the GATT setup path already did.
- ISO controller buffer checks include the four bytes of sequence/SDU metadata.
  Receive-only sessions no longer require transmit buffers or trigger the
  playback scheduling-gap detector after 250 ms without transmission.
- Settings and pairing keys are written to a complete, flushed temporary file
  and replaced by same-directory rename. Readers see the previous or the new
  snapshot. A failed replacement preserves the previous file and removes the
  temporary file.
- WinUSB device lookup now matches the actual PnP instance passed by enumeration.
  It previously ignored that argument and opened the first registered WinUSB
  interface, which misidentified adapters and prevented trying a second adapter.
- Non-object JSON input no longer panics the agent. UI shutdown no longer
  disposes a semaphore while queued command writers may still need to release it.
- Publication no longer deletes an existing package before discovering that
  its executables are locked. Required artifacts and write access are checked
  first, a directory rename retains a rollback copy, and failed promotion
  restores it. PowerShell failures now stop the BAT instead of printing a false
  success or nesting the stage inside the old installation. Regression tests
  cover complete promotion, locked targets, incomplete stages, and path bounds.
- 44.1 kHz radio configuration is rejected before setup. Its LC3 frames contain
  360/480 samples and require 8.163/10.884 ms framed ISO timing; the previous code
  used ordinary 7.5/10 ms timing and could panic in debug builds. It is no longer
  offered as a new setting. An existing unsupported saved choice stays visible
  until repaired. Windows audio at 44.1 kHz still resamples to a supported stream
  rate, normally 48 kHz.

The existing Range / stability profile and its 1M control/audio defaults remain.
These changes fix host-side failure modes; they do not increase the adapter's
transmit power or establish a measured range improvement.

## Verification

Run from the project root:

```powershell
.\dev\scripts\cargo.cmd test --all-targets
python dev/tests/discovery-regression.py
python dev/tests/agent-protocol-regression.py
powershell -NoProfile -ExecutionPolicy Bypass -File dev/tests/publish-regression.ps1
& '.\dev\BUILD application.bat' --no-pause
```

The protocol test launches the actual compiled agent, isolates APPDATA, and
checks quit, closed input, invalid JSON and scalar/array commands without
opening a Bluetooth adapter. It can also test the packaged executable:

```powershell
python dev/tests/agent-protocol-regression.py --agent release/OpenLEAudio4/OpenLEAudio4.Client.exe
```

To package a separate candidate while the installed application is running:

```powershell
python dev/scripts/package-release.py --app-dir path/to/staged/OpenLEAudio4
```

This creates a complete directory under `dev/artifacts` and a verified ZIP plus
SHA-256 file in the project root. It deliberately does not replace existing
package outputs, include runtime-data JSON, or modify the running installation.

The Windows execution sandbox may deny rename in its injected temporary
directory. For persistence tests in that environment, set TEMP and TMP to a
directory under the writable workspace before running cargo. This is a test
environment restriction; the tests must still exercise real file replacement.

Results: 249 library tests, 16 agent tests, six LC3 integration tests, C#
discovery/startup regression tests, 43 native C checks, four agent process
scenarios, and four publication scenarios passed. The Rust release binary and
WinUI Release build/publish compiled successfully. NuGet reported NU1900 because
its vulnerability-data endpoint was unavailable; compilation reported no errors.

The installed 4.0.1 application was running during validation. The old publishing
script partially removed unlocked runtime files, then incorrectly reported
success. Missing files were restored from the existing 4.0.1 archive; files held
by the running processes were preserved. A separate complete 4.0.2 package is
provided for extraction after exiting the running application. No headset stream
or driver binding was deliberately stopped for this build.

Radio range, audible stereo continuity, real cancellation races, and reconnect
after walking out of range require a headset test. The automated suite does not
simulate the entire controller or RF environment.

## Protocol references

- [Bluetooth HCI functional specification](https://www.bluetooth.com/wp-content/uploads/Files/Specification/HTML/Core-54/out/en/host-controller-interface/host-controller-interface-functional-specification.html): packet flow control, Number Of Completed Packets, and ISO buffer sizes.
- [Linux HCI wire structures](https://github.com/torvalds/linux/blob/master/include/net/bluetooth/hci.h): `hci_comp_pkts_info` and `hci_ev_num_comp_pkts` independently confirm the paired layout.
- [Bluetooth Basic Audio Profile](https://www.bluetooth.com/wp-content/uploads/Files/Specification/HTML/16212-BAP-html5/out/en/index-en.html): 44.1 kHz effective frame durations and framed QoS configurations.
- Vendored `core/vendor/liblc3/include/lc3.h`, section “About 44.1 KHz sample rate”: codec sample counts and timing scaling.

## Hardware validation checklist

1. Start the packaged application, select Range / stability, and confirm the
   logged ACL PHY and audio configuration. Play a left/right identification
   recording and check that both channels remain correctly assigned.
2. Put CPU load on the PC, then remove it. Check for recovery of both channels
   and compare backpressure/underrun logs with the same test on the previous build.
3. Walk out of range and return. Check automatic reconnect; then manually
   disconnect during an attempt and confirm that no connection remains active.
4. Restart after the headset has changed its private address, with other BLE
   devices nearby. Check discovery/reconnect of the saved device.
5. If used, enable the headset microphone and verify simultaneous playback,
   input routing, and stream recovery.

Read-only adapter lookup was checked against the installed ASUS 0B05:1D70 and
Realtek 0BDA:A729: the new lookup finds the ASUS WinUSB instance and rejects the
Windows-owned Realtek as an OpenLEAudio interface. The running older agent owned
the ASUS, so a second WinUSB open correctly failed with Windows error 5.
